# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The view lives in the address bar: the URL fragment holds the projection, the chart's centre (`ra`, `dec`, degrees), the position angle of its top (`pa`: the topmost point of the stereo disc, the middle of the pinhole frame's top edge; north through east), the field of view, the pinhole frame's aspect ratio and size, and the layers that are on, e.g. `#p=pinhole&ra=83.82&dec=-1.2&pa=0&fov=40&ar=1.5&size=1.3&layers=lines,bounds`. It follows the view 0.3 s after it comes to rest (replacing, never adding to the Back history), a reload or a shared link opens the same view without a morph, and a link pasted into an open tab takes over. A plain visit keeps a plain address until something changes.
- A notice over the chart when the catalog does not load ("Couldn’t load the star catalogue." or the constellation lines or boundaries by name) with **Try again**, which fetches only what is missing; a load slower than 0.5 s says "Loading the star catalogue…". Before, a backend that was down left an empty white disc and no word.
- SVG and PDF export of the chart say "Preparing the SVG…" past 0.6 s and "Couldn’t export the SVG. Try again in a moment." when they fail, as the PDF document already did; a second export waits for the first. Before, a failure was only logged to the console.
- Stars load in two stages, as SPEC.md asks: `/api/catalog/bright` (about 520 stars, 7 KB gzipped) is drawn as soon as it arrives and `/api/catalog/full` (8,870 stars, 103 KB gzipped) replaces it; both requests start together.
- Catalog caching. The backend serializes and gzips the default answer of the four catalog routes once at startup and sends it with `Cache-Control: public, max-age=86400, stale-while-revalidate=604800` and an `ETag`; `If-None-Match` gets a `304`. A request costs it under a millisecond instead of filtering and serializing the whole catalog each time, and a returning visitor makes no catalog request at all for a day. A returning visitor's browser asks for nothing; a CDN in front would spare the server the first visits too.
- PDF document in the generator: **+ Add to PDF** in the header places the chart as the preview shows it on the first page with room (a new A4 page if none), and a pages panel floats on the left of the chart: page thumbnails with their charts, a red ⊖ on hover to delete a page (with an Undo toast for 6 s, also `⌘Z`/`Ctrl+Z`), ⊕ to add a page, a tab to collapse it to the page count (collapsed by default on phones), and a click on a page opens the page editor. The export menu gets a "PDF document" row ("N pages · A4") that downloads every page as one PDF. The document is kept in `localStorage`.
- The page editor, opened from a page in the panel: the previous, current and next page side by side over the dimmed app, a strip of mini pages (with ⊕) below and ⊗ to close. Charts move by dragging and resize by their corners, both snapping to fractions of the page's content box and to the edges and centres of the other charts, with guides drawn; a chart let go over a neighbouring page moves there. Each page has its own portrait/landscape toggle, and charts that no longer fit are placed again. From the keyboard a focused chart nudges with the arrows (Shift: 10 mm), steps its size with + and −, moves to the page before or after with Page Up/Page Down and is removed with Delete (with an Undo toast); a selected chart shows the same commands as a small toolbar, for touch and for anyone who cannot drag.
- `POST /api/export/document` (and its SvelteKit proxy, which streams the file back): charts placed on pages in mm come back as one multi-page PDF, each page exactly its requested size (A4 portrait or landscape) and an empty page blank. Pages are built as SVG with every chart nested under its own id prefix, converted with `svg2pdf::to_chunk` and assembled with `pdf-writer`. A document holds up to 100 pages, 50 charts on a page and 200 charts in all (a chart costs about the same to draw whatever its size), and two documents are converted at a time; the editor keeps to the same limits and shows the backend's reason when it refuses a document.
- `view.px` in `RenderConfig`: the length of one preview px in view units. Star and planet radii, line widths and text scale with it, so a chart sized in mm keeps its stars the same size on paper however large it is drawn.
- `style.chart_outline` strokes the sky's edge 1 preview px wide, and `style.background_color: "none"` paints no background, for charts on white paper.
- About dialog after ray.so's: a description and the full shortcut list, opened from the header or with `?`.
- `⌘K`/`Ctrl+K` toggles the export menu (arrow keys move through the formats); `⌘S`/`Ctrl+S` saves a PNG.

- One service in production. The frontend builds to static files (`adapter-static`, each also packed as `.br` and `.gz`) and the backend serves them next to `/api/*` when `STATIC_DIR` names the build: hashed assets cached for a year, the page revalidated on every visit, `404.html` for a path that is no file, `/generator` still a `308` to `/`. A `Dockerfile` builds the image (backend binary plus the static build, 111 MB); it idles at about 6 MB of memory and starts in about 0.3 s. `PORT` sets the port, `GET /api/health` is the health check.
- An export budget (`backend/src/limits.rs`): `/api/export` and `/api/export/document` are rationed in charts by a token bucket per client (1600 units of burst, 1 a second; a PDF chart costs 4, an SVG 1) and one for the whole server (8000, 2 a second), and answer `429` with `Retry-After` past either. The page shows the backend's reason when a document is turned away. At most 4 single charts are converted at a time, as 2 documents already were.
- SVG exports, the page editor's chart previews among them, are gzipped for a client that takes gzip: 464 KB becomes 97 KB for a full-sky chart with every layer.

- Motion, all of it left out when the system asks for less (`prefers-reduced-motion`):
  - The sky glides on after a drag at the speed it was let go with and slows to rest in about half a second. A pointer that stopped before it was lifted leaves the sky where it put it.
  - Stars fade in when they arrive: the bright ones on load, then the fainter ones of the full catalogue over them, so the two-stage load no longer pops.
  - The wheel (Ctrl + wheel) zooms smoothly to where it was sent instead of in steps; notches add up.
  - A link pasted into the open tab is flown to: the sky turns the short way and zooms as it goes. Across projections it is still a cut.
  - The layers panel fades in over a short slide from the right, and where the chart has to make room for a panel it glides to its new place (a transform, so nothing is laid out again on the way).
  - The export button shows a check for a moment once a file is saved, PNG included, and a turning ring only when an SVG or PDF is still being drawn after a third of a second; most are done long before.
  - The layer count on the Layers button gives a small bump when it changes; the catalogue notice arrives as the toast does; a dismissed toast leaves instead of vanishing.
  - A page that is deleted closes up and the panel shortens with it, as it lengthens when one is added; the last page takes the panel along, which slides away to the left as it came. Undo, and the ⊕ of the panel, bring a page in the same way.
  - Add to PDF shows the chart going to its page. The page appears first with the chart's place on it empty (a new page grows into the list; the first one arrives with the panel, which slides in from the left). A copy of the chart, drawn exactly as the page thumbnail draws it, comes up over the preview, shrinks along the way and stops on that place, where the thumbnail's own drawing takes over from it with nothing changing under the eye. Charts already on the page move aside over the same time, so the room is seen being made.
- Text on a page of the PDF document. **Add text** by a page's name in the page editor puts a text in the topmost free place on the page, as wide as that place (the content box's width on a clear strip), open for typing. A text moves like a chart (by dragging, to a neighbouring page too, or with the arrows, Shift for 10 mm, Page Up/Page Down); its two sides set its width and its lines wrap to it, so its height is its lines'. Enter or a double click types in it, Escape keeps what was typed, and a text left empty goes. Its toolbar sets the font (PT Serif or PT Sans), the size (8 to 48 pt, also + and −), bold, italic and the alignment, and removes it (also Delete, with Undo). The page thumbnails and the strip show it.
- A text can be turned: the knob over it turns it about its centre as the pointer goes round, reading the angle out, and with Shift held it goes to the nearest right angle (upright, on either side, upside down); the toolbar's turn button and R turn it a quarter clockwise, Shift+R back. A turned text keeps on the page by what it takes up there, may be as long as the page is tall when on its side, and stands upright while it is typed in. The PDF sets it at the same turn.
- Tables on a page of the PDF document. **Add a table** by a page's name in the page editor puts one in the topmost free place: a list of what is on a chart, brightest first. As on a SkyGen worksheet it is a title in bold ("Messier objects", "Stars") over the names alone, three to a row, each in the middle of its column, as wide as its names, so a second table goes beside the first at the right margin. Its toolbar says what it lists (the Messier objects in the chart's field, or its bright stars by their proper names), in 1 to 40 rows, and how it looks: **Names**, or **Details**, a row an object under a ruled header (a Messier object's name, type, constellation in full and magnitude; a star's name, right ascension, declination and magnitude). A table is a text that is not typed: it reads the chart nearest to it, or the one it is told, and is moved, made wider (its columns share out the width), turned, copied, removed and set in a font and a size as a text is. The PDF sets it a line a cell, so it looks there as it does in the editor.
- A table made narrower than its columns gives way inside its frame: in a table of names the three columns narrow alike and the names are cut with an ellipsis; in a table of details the columns of words give way, the widest first, and the figures keep theirs. It cannot be made narrower than holds all of it.
- The lines a chart, a text or a table snaps to while it is resized show only with Shift held, as they already did while it is carried; before, a line ran down the page through every resize. A text or a table being made wider or narrower no longer draws the page's margins either.
- A pinch off the chart no longer zooms the page itself. In Safari two fingers pinched over a panel or in the page editor zoomed the whole app, which then panned up, down and sideways with its far edges out of the window. A pinch on the chart zooms the sky as before, and the browser's own zoom (⌘+ and ⌘−) is untouched.
- A chart, a text or a table being resized is drawn on a layer of its own, as one being carried is. In Safari, with the page zoomed to anything but a whole number of pixels, a text or a table made narrower left hairlines down the page where its side had been.
- A table names 150 stars instead of 77, and in Russian by their Russian names (Сириус, Вега, Альфа Центавра). The list is SkyGen's, whose names are Stellarium's; each star was checked by its place against the IAU Catalog of Star Names and the Hipparcos catalogue, and by its names against Stellarium's modern sky culture and its Russian translation. Left out of SkyGen's list: Atik (two stars carry it in Stellarium), two names Stellarium does not give those stars, and Meridiana, which SkyGen had in the wrong place and far too bright.
- A table's words in Russian: EN / RU in its toolbar sets its title ("Звёзды", "Объекты Мессье"), its header, the kinds of objects and the constellations in that language (a star's name and a Messier object's are the same in both). A new table starts in the browser's language.
- The **Worksheet** template is laid out after SkyGen's: its eight tasks, in English or Russian, and under them the names of the chart's stars and of its Messier objects in two tables side by side, over the chart. Laid out again, a table keeps the rows and the look chosen for it.
- A text or a table may read a chart on another page: with charts elsewhere in the document, its toolbar's "Reads" row lists them ("Page 1 · chart 1"). Moved to a page with no chart, it goes on reading the chart it read, so a table moved to a page of its own still lists its sky; told a chart, it keeps to it wherever it is moved.
- `POST /api/export/document`: a line of a text may carry an `anchor` and a `bold` of its own (a table's cell), and a text may carry `rules` (hairlines drawn and turned with it). A text now holds up to 400 lines.
- Page templates. A button on a page's thumbnail in the pages panel (across from its ⊖) and by its name in the page editor opens "Lay page N out as": five tiles, each drawn with that page's own charts as the template would place them. **Charts only** is the arranger's layout with no template text; **With a caption** gives each chart a page under a title, with a caption that reads it; **Two skies** stands two charts side by side or one over the other, whichever shows them larger; **Finder card** is made of one wide sky (the page's first disc, else its first chart) and an object chosen on it: its tile opens a list of the Messier objects on that sky, brightest first, with a search (a number, a name, a kind, a constellation), the close-up's field (10°, 20° or 40°) and the card drawn beside the list for the object under the pointer; a click draws the close-up (the same sky at the same hour through a 3:2 frame with the object in its middle and north up), names it in its caption, and rings its place on the wide chart. Chosen again for the same sky, the new close-up replaces the old one; other charts on the page go on pages of their own. **Worksheet** is a line for the name, the sheet's number, tasks, the chart, and its key upside down at the foot. Charts take their places in their order on the page, and charts past a page's places go on new pages after it. Under the tiles, the orientation of the pages to make and **Swap charts**. A click lays the page out, with an Undo toast that also takes the new pages away. Laid out again, a text keeps what was typed in it where the new template has the same part for it (a title, a chart's caption), and text the page's owner added stays where it is. A template that needs more charts than the page has, or more pages than the document has room for, says so on its tile.
- Templates write in Russian as well as English. **EN** / **RU** under the tiles (Russian to begin with in a browser set to Russian) redraws them in that language: the titles ("Карта неба", "Два неба", "Поисковая карта"), the captions ("Широта {lat} · звёздное время {lst}", "Центр {ra}, {dec} · поле {fov}", and "· поле {fov}" after an object's name under a close-up), and a worksheet's line for the name and its three tasks. What a field shows ("56° N", "13h 45m"), an object's name, a key and a sheet's "№ 1" are the same in both. Laid out again in the other language, a text that still says what a template wrote is written afresh in it and one that was typed over is kept, as between templates; a worksheet's header and tasks now count as a template's words too, so a header nobody typed in no longer keeps a face it was given by hand. On a narrow screen the picker's footer wraps instead of squeezing "Swap charts" onto two lines.
- A page remembers the template that laid it out, so turning it keeps the layout. The orientation toggle of a page in the editor used to hand a templated page to the arranger, which lays out charts and knows nothing of text: the charts were placed again as if alone and the title and captions carried along in proportion, off the charts they belonged to. Now the page is laid out by its template for the other orientation: two skies go from one over the other to side by side with their captions under them, a finder card keeps its own close-up and the ring on its sky (no new close-up is made, and the close-up is not sent to a page of its own), a worksheet keeps its number and has its key at the foot of the turned page. Every text keeps its words, its face and the chart it reads; text the page's owner added moves with the content box as on any turn. The layout depends on the orientation alone, so turning back gives the page it was. The memory (`template` on a saved page: the template's id and its language) lasts while the page is what the template made: adding, removing, moving, resizing or turning a chart or a text on it by hand, Add to PDF landing there, or a paste, forgets it, and the page then turns like any other; typing in a text, changing its face or the chart it reads does not. "Charts only" is the arranger's layout and is not remembered.
- `GET /api/catalog/messier`: the Messier catalogue (number, name, kind, constellation, magnitude, RA and Dec in degrees), cached like the other catalog routes; the page asks for it when the template picker opens.
- `marks` in `RenderConfig`: places ringed on a chart, each a centre (`ra_deg`, `dec_deg`) and a `radius_deg`, drawn in the app's accent inside the sky's edge. A finder card rings where its close-up looks.
- The ring a finder card puts on its wide sky shows on the small drawings of the page too: the thumbnails of the pages panel, the tiles of the template picker and the card beside its list of objects (where it moves from object to object as the pointer does). It is the backend's ring (the same points a degree apart, in the accent `#d34b4b`), projected as the thumbnail projects its stars and stroked 1 px wide over them; the part of a ring that is off the chart is not drawn. Before, the ring was only in the editor's vector preview and in the PDF, and a finder card looked like two unrelated charts in the panel.
- Copy, cut and paste in the page editor: `⌘C`/`Ctrl+C` copies the selected chart or text, `⌘X` cuts it, `⌘V` puts a copy on the page being shown at its own size, where it was copied from if that is free, else in the free place nearest to there, with the focus on it and an Undo toast. On a page with no room for it the copy is not made smaller: it goes over what is there, its middle under the pointer. Words copied anywhere else paste as a new text, and a copied text pastes as words into any other program. While a text is typed in, the keys are the field's own.
- Fields in a text: `{lat}` and `{lst}` are the latitude and the sidereal time of whoever sees the sky of a stereographic chart (its centre is their zenith), `{ra}` and `{dec}` the centre of any chart, `{fov}` its field, `{date}` and `{time}` when it was made. A text reads one chart and changes with it: the nearest to it (a gap to the side counted double, so a caption reads the chart it stands under), or, on a page with two charts or more, the one its toolbar tells it by number ("Reads: Nearest · 2, 1, 2"); the charts show their numbers meanwhile, the one being read in the accent. While typing, a row under the toolbar inserts a field at the caret.
- A field takes a precision: `:0`, `:1` or `:2` after its name is the number of decimals of the last unit it shows, so `{lat:1}` is "55.8° N", `{dec:2}` "+24.12°", `{fov:1}` "42.4°" and `{lst:1}` or `{ra:1}` "13h 45.2m" (decimals of the minute). Without one a field says exactly what it said before: whole degrees, whole minutes. Rounding carries (59.96 minutes is the next hour's 00.0, the day's last minutes are 0h 00.0m) and a hair south of the equator is "0.0° N" and "+0.0°", never a negative nothing. `{date}` and `{time}` take none, and a suffix a field does not take (`{lat:9}`, `{lat:x}`, `{date:1}`) leaves it as typed, like an unknown name. The buttons that insert a field still insert the plain one; their tooltips name the suffix.
- `POST /api/export/document` takes `texts` on a page: each already broken into lines by the editor, which the backend sets where it is told to. Both sides hold the same font files (PT Serif and PT Sans, four faces each, in `frontend/static/fonts`: the page loads them from `/fonts/`, the backend carries them in its binary), so the PDF breaks its lines where the editor did; the fonts are embedded as subsets and the text can be selected.
- An empty page can be deleted in the page editor: a button on the page's label, beside its orientation toggle, or Delete with the focus on the page. The page that takes its place is shown, the editor closes with the last one, and the toast's Undo brings the page back. A page with charts on it is still deleted from the pages panel only.

### Fixed

- In the page editor a chart dragged from a neighbouring page onto the current one is in sight all the way. The current page was stacked above its neighbours and the chart stays its own page's child while it is dragged, so it went under the current page and only showed once it was let go; it was dimmed with its page as well. The page a chart is dragged from now stacks above the rest, and a neighbour is dimmed by a veil under the dragged chart instead of by making the whole page translucent.
- The arrow keys keep turning the sky after a control is clicked with the mouse. A click on Stereo or Pinhole left the focus on that radio group, which steps its selection with the arrows, so they flipped the projection until a click elsewhere let go; a switch in the layers panel, its close button, the Layers button and a page thumbnail (when the editor it opened was closed again) held ↑/↓ the same way. A mouse press no longer moves the focus onto these controls; reached with Tab they take the arrows as before.
- Hovering a page in the pages panel no longer nudges the other pages. The lifted thumbnail's ⊖ reached 1.4 px past the list's padding (2.5 px for a landscape page), which grew the list's scrollable width, and in a right-to-left scroller WebKit shifted every other page by that much. The padding now holds it.
- Shift-dragging a corner of the pinhole frame no longer flickers between a large square and a small one. The square took "the axis that moved further from the start", so with the pointer out to one side and in on the other by about as much (right and up from the bottom-right corner, say) it flipped between the two sizes on every pixel across that diagonal. Its side is now the larger of the two the pointer asks for, which follows the pointer without a jump; from an edge it is the dragged axis alone.
- SVG and PDF export from the generator: the request was not a `RenderConfig` and every export failed with 422. The page now sends the preview's camera (`view`), field of view, layers and colours, and the backend draws the same chart, pinned to the preview by a shared golden fixture.

### Changed

- In the page editor a chart in the hand is no longer held to the paper. It used to be drawn at the place it would land, so it stopped at the margins, jumped from guide to guide and hopped between pages as the pointer crossed them. Now it follows the pointer anywhere in the editor, over the gap between pages, the bar and the strip, lifted with a shadow and nothing else: no guides, margins or outlines are drawn while it is carried, and the other charts put their frames and toolbars away. Holding Shift shows the lines it would snap to. Let go, it settles into its place, snapped to the grid as before. The page it lands on is the one its centre is over, or the nearest one within 40 px: a chart let go a little short of a page, or past its edge, is brought onto it at the nearest place it may be. Further out than that it goes back where it was. The shadow is a box-shadow on a layer of its own; as a drop-shadow filter it left smears behind the chart in Safari.
- ⊕ in the pages panel adds a page and nothing more: the page grows into the list, without the flash and bump that lead the eye to a page after Add to PDF. The new page comes to lie where ⊕ was, under the pointer, and is not treated as hovered (no lift, no ⊖) until the pointer has moved; one click no longer sets off four effects.
- The pages list has no scrollbar of its own (the system's grey bar down the side of so small a panel was the one thing in it not drawn here) and fades only at the edge that pages run under, by as much as there is to scroll that way. At rest at the top there is no fade above, which used to dim the first page's ⊖. The list also starts 22 px below the panel's edge instead of 14, so that ⊖ no longer sits hard under it.
- Every page in the pages panel is the same width, whichever way it is turned: a landscape page is drawn at a smaller scale and comes out lower, not wider. At one scale for both, the panel jumped 36 px wider (and moved the chart beside it) the moment a landscape page was added or a page was turned.
- Page thumbnails draw smaller stars (a radius of 0.3 to 0.85 px, from 0.4 to 1.2): on a 60 px chart the bright ones ran into each other.
- Layers is a panel beside the chart, not a popover over it. The popover opened above the dock and covered the lower right quarter of the disc, just where one looks for a switch's effect. On a screen with room for it the dock's Layers button now shows a panel at the right of the chart area, which stays open while the sky is turned (it is no menu: a click elsewhere or Escape elsewhere leaves it) and is remembered for the next visit. The chart keeps clear of it as it does of the pages panel: it stays in the middle while it fits there, moves over just far enough in a narrower window, and only then shrinks; the pages panel now moves the chart the same way where it used to shrink it from both sides. From the keyboard the focus goes into the panel, ↑/↓ walk its rows, and Escape there closes it and returns to the button. A phone keeps the popover above the dock.
- The SvelteKit server is gone, and with it the `/api/*` proxy routes and `BACKEND_URL` at run time: the page calls the backend on its own origin. In development the Vite dev server forwards `/api` to `BACKEND_URL` (default `http://localhost:8080`). `adapter-static` replaces `adapter-auto`, which had no target to build for on a plain host.
- A single chart is drawn on the blocking pool, not on the async workers, where a PDF held up every other request for its 60 ms.
- The system fonts are loaded once, not for every PDF: on a machine with many fonts that was a seventh of an export's CPU.
- The image runs glibc's allocator with two arenas and the trim and mmap thresholds pinned at 128 KB, so memory goes back after a large export: the process settles at about 22 MB instead of 30-70 MB, at the same speed.
- `/api/catalog/bright` and `/api/catalog/full` send a star as `{ "v_mag", "ra", "dec" }` only. The HIP number and the unit vector (`hip_id`, `x`, `y`, `z`) are gone: the page never read them and works the vector out from `ra` and `dec`. The full catalog went from 950 KB (290 KB gzipped) to 414 KB (103 KB gzipped).
- `RenderConfig`: an optional `view` (camera basis and chart size) replaces the observer for orientation, so `latitude`/`longitude` are only required without one; `style.chart_color` fills the sky; `layers.constellation_boundaries` draws the IAU boundaries; `datetime` accepts RFC 3339.
- The backend draws constellation lines as great-circle arcs and traces reference circles in 1° steps, with the preview's line widths and opacities. Line opacity is `stroke-opacity` rather than element `opacity`, which made svg2pdf wrap every line in a transparency group of its own (a PDF about 2.4 times larger and slower to display).
- Bottom dock: a Stereo/Pinhole segmented control and a Layers popover with grouped switches replace the row of labelled toggles. The two projections stand 4 px apart, like the dock's other controls; flush, the lit one ran straight into its neighbour's label.
- The pinhole frame has its own overlay (corner brackets, edge pills, a size readout while dragging, keyboard-resizable edges) instead of Moveable, which is no longer a dependency.
- Header, after ray.so: Export is a tinted split button that names the format it saves ("Export PNG"), and its menu says what each format is for and shows ⌘S. About is a "?" icon on phones, and the header fits a 320 px screen.
- Pinhole opens from a full-sky stereo view at 100° instead of the 120° maximum, so the frame can still be widened; switching straight back restores the view you left.
- Apex is now a single tool: the star-map generator is the only page and is served at `/`; the old `/generator` URL permanently redirects (308) to `/`.
- `SPEC.md` narrowed to the generator; the original full specification is kept as `legacy/SPEC.md`.

### Removed

- The header's Format button, which did nothing.
- Sky Quiz: game API (`/game/api/*`), question factory, SQLite game sessions (`sqlx` database and migrations) and scoring/ranks in `rust-core`.
- AstraEtudes: orbital simulator API (`/api/compute`) and the RK4 mechanics in `rust-core`.
- The 110 Messier photos (`/images/*`). The Messier catalog itself stays in `rust-core` for a future map layer.
- Landing, games and astra-etudes frontend pages.
- All of the above is archived under `legacy/` for reference only; it is not built, compiled or routed.

## [0.1.0] - 2026-05-21

### Added

- Initial Rust + SvelteKit rewrite of the project as "Apex".
- `rust-core` library: catalogs (HIP, Messier), projections (stereographic, pinhole), scoring and orbital mechanics.
- `backend` HTTP API (Axum + SQLx + SQLite): catalog endpoints, PDF/SVG export, orbital simulator, Sky Quiz session API (5 game modes).
- `frontend` SvelteKit web application: landing page, star-map generator with real-time canvas preview, Sky Quiz games, AstraEtudes orbital simulator.
