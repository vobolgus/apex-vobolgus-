# Apex — Project Specification

## Задача проекта

Apex — веб-сервис генерации карт звёздного неба: настраиваемые карты
в формате PDF для наблюдений, олимпиад и уроков астрономии. Стереографическая
и pinhole-проекции, экспорт с легендой и логотипом.

Целевая аудитория: школьники и студенты, педагоги астрономии, любители.
Языки интерфейса: русский и английский.

Архивные части проекта (Sky Quiz, AstraEtudes, мобильное приложение) описаны в [`legacy/SPEC.md`](legacy/SPEC.md).

## Стек

### Shared Core — Rust (библиотека)

Ядро проекта. Используется сервером.

```
rust-core/
├── catalog/       ← HIP (Hipparcos), Messier, созвездия
├── coords/        ← экваториальные координаты → единичные векторы
├── time/          ← юлианская дата, звёздное время
├── projections/   ← стереографическая, pinhole, цилиндрическая
└── planets/       ← эфемериды Солнца, Луны и планет
```

### Backend — Rust (Axum)

Минимальный сервер. Вызывается только там где нужна серверная логика.

| Endpoint | Что делает |
|---|---|
| `POST /api/export` | Генерация PDF через `plotters` крейт |
| `GET /api/catalog/bright` | Каталог звёзд ярче 4.0m (первый этап загрузки) |
| `GET /api/catalog/full` | Полный каталог до 6.5m (второй этап, фоновая загрузка) |
| `GET /api/constellations` | Линии созвездий |
| `GET /api/constellation-boundaries` | Границы созвездий |

Базы данных нет: каталоги загружаются в память при старте сервера.
Целевое потребление памяти: **20–40 MB** в idle на Railway free tier.

### Web Frontend — SvelteKit

Одна страница — генератор на `/` (старый адрес `/generator` перенаправляет на неё).

| Раздел | Технология |
|---|---|
| Генератор (`/`) | Canvas 2D — превью в реальном времени (JS). `POST /api/export` только при скачивании |

**Послойная загрузка каталога (LCP):**
Каталог грузится в два этапа чтобы карта появилась мгновенно:
1. При открытии страницы — микро-пакет: ~500 звёзд ярче 4.0m (~15 KB). Карта рисуется сразу.
2. В фоне асинхронно — полный каталог до 6.5m (~9000 звёзд, ~150 KB gzip). Подгружается незаметно.

Все проекции для превью считаются локально в JS — сервер не задействован.

## Экраны

### Генератор (`/`)

Единственная страница сервиса, отдельной навигации нет.

1. **Форма + превью** (ray.so layout)
   - Панель: проекция, место/время, слои, звёздная величина
   - Canvas превью обновляется в реальном времени
   - Кнопка "Скачать PDF" → передаёт `RenderConfig` на сервер → loading → файл

2. **Loading** — индeterminate спиннер, пока сервер генерирует PDF

### Глобальные

- **Настройки** — язык, тема
- **404** — тёмный, "объект не найден в каталоге"

## Контракт рендеринга генератора (RenderConfig)

Чтобы превью на Canvas и PDF-экспорт выглядели идентично, фронтенд
при нажатии "Скачать PDF" передаёт на сервер полный конфиг состояния:

```json
{
  "projection": "stereo" | "pinhole",
  "datetime": "2025-06-01T22:00:00Z",
  "latitude": 55.75,
  "longitude": 37.62,
  "magnitude_limit": 6.5,
  "fov_deg": 60,
  "aspect_ratio": 1.5,
  "constellation": "ORI",
  "tilt_angle": 0,
  "layers": {
    "ecliptic": true,
    "equator": false,
    "galactic_equator": false,
    "planets": true,
    "horizontal_grid": false,
    "equatorial_grid": true,
    "constellations": true,
    "constellation_names": true,
    "zenith": false,
    "poles": false
  },
  "style": {
    "star_color": "#ffffff",
    "constellation_line_color": "#4488ff",
    "grid_color": "#333355",
    "background_color": "#000010",
    "font_family": "Inter",
    "magnitude_scale": 1.0
  },
  "print_info": true,
  "footer_text": "apex-skychart.ru"
}
```

Сервер обязан следовать этому конфигу точно. Любые изменения стиля
вносятся в одном месте (фронт) и автоматически отражаются в PDF.

Камеру превью фронтенд передаёт в необязательном блоке `view`. С ним сервер
рисует ровно то, что видно на Canvas, а `latitude`, `longitude`,
`constellation` и `tilt_angle` для ориентации не нужны. В примере только новые
поля:

```json
{
  "view": {
    "right": [-0.6, 0.8, 0.0],
    "up": [0.0, 0.0, 1.0],
    "forward": [0.8, 0.6, 0.0],
    "width": 1104,
    "height": 1104
  },
  "fov_deg": 180,
  "layers": { "constellation_boundaries": true },
  "style": { "background_color": "#0a0a0b", "chart_color": "#ffffff" }
}
```

- `right`, `up`, `forward` — оси экрана и центр карты в экваториальной
  системе. Сервер берёт их как есть, поэтому и сторону, в которую читается
  небо, задаёт фронт.
- `width`, `height` — размер карты в пикселях превью. Радиусы звёзд и толщины
  линий тоже в них, поэтому пропорции совпадают с экраном.
- `fov_deg` с `view` — поперёк диска для `stereo` и по горизонтали для
  `pinhole`.
- `chart_color` — заливка самого неба (диска или кадра), `background_color` —
  всё вокруг; `"none"` — без фона, сквозь карту видна бумага.
- `datetime` — RFC 3339, как в примере выше.

Проекция с обеих сторон сверяется по `backend/assets/golden/view-projection.json`.

Для печати (PDF-документ из нескольких карт) есть ещё два необязательных поля:

- `view.px` — длина одного пикселя превью в единицах `width`/`height`
  (по умолчанию 1). На него умножаются радиусы звёзд и планет, толщины линий и
  размеры текста. Документ передаёт размер карты в мм и
  `px = 186 / 1104` (мм на пиксель превью), поэтому звёзды на бумаге одного
  размера, как бы ни масштабировали карту.
- `style.chart_outline` — цвет обводки края неба (диска или кадра) толщиной в
  1 пиксель превью: белый диск на белой бумаге без неё не виден.

Сам документ уходит на `POST /api/export/document` (страницы в мм, на каждой
карты со своим `RenderConfig`), ответ — один многостраничный PDF; формат в
`backend/API.md`.
